## Overview

The API's interactive documentation is **Swagger UI**, served by `Swashbuckle.AspNetCore.SwaggerUI`. Only the UI comes from Swashbuckle: the OpenAPI document is still generated by `Microsoft.AspNetCore.OpenApi` (`AddOpenApi` / `MapOpenApi`), so its schema transformers and request examples are unchanged.

## How It Fits Together

| Piece | Where | What it does |
| --- | --- | --- |
| `AddOpenApi(...)` | `OpenApiExtensions.ConfigureOpenApi` | Generates the `v1` document; `ApiTitleDocumentTransformer` sets the title, `RequestExampleSchemaTransformer` adds request body examples, and `MultipleOkResponsesOperationTransformer` and `ApiSecurityOperationTransformer` shape operations (see [below](#document-transformation)). |
| `MapOpenApi()` | `OpenApiExtensions.ConfigureOpenApiEndpoints` | Serves `/openapi/v1.json` (anonymous, outside Production). |
| `UseSwaggerUiIfEnabled` | `OpenApiExtensions`, called from the ApiPipeline.NET pipeline | Serves Swagger UI at `/swagger`, pointed at `/openapi/v1.json`, with its own CSP. |

Swagger UI is **middleware**, not an endpoint. The fallback authorization policy would answer 401 for it, so it runs inside the pipeline before authentication: `.WithMiddleware(a => a.UseSwaggerUiIfEnabled(app.Configuration))` in [MiddlewareExtensions.cs](../../src/GSS.Api/Extensions/Middleware/MiddlewareExtensions.cs). See [API Request Pipeline](../architecture/api-pipeline.md#pipeline-order).

## Accessing It

- Local: `dotnet run --project src/GSS.Api`, then `https://localhost:7109/swagger` (the launch profile opens it).
- Compose: `https://localhost:7109/swagger` (accept the self-signed certificate).
- Raw document: `https://localhost:7109/openapi/v1.json`.

The document declares the bearer scheme and the four `x-app-*` caller headers. Swagger UI's **Authorize** dialog stores them once; `ApiSecurityOperationTransformer` lists the bearer token on authenticated operations and adds the caller headers only to actions that actually validate them.

## Environments

Both the document and the UI are available in every `AppSettings:Environment` except `Production`. In Production neither is mapped, so `/swagger` and `/openapi/v1.json` fall through to the fallback policy (401).

## Document Transformation

List actions using the shared pagination helper can advertise three HTTP 200 shapes with `ProducesResponseType`. Requests without paging inputs return a list. Send `page` for numbered pagination or `pageSize` to start cursor pagination, then pass the returned `nextCursor` as `cursor`. Request an exact total with `includeTotal=true`.

The document is shaped by `Microsoft.AspNetCore.OpenApi` transformers registered in `AddOpenApi`, not by rewriting the JSON afterwards:

- **Paths**: the versioned API Explorer runs with `SubstituteApiVersionInUrl = true` ([ApiVersioningExtensions.cs](../../src/GSS.Api/Extensions/Features/ApiVersioningExtensions.cs)), so route templates such as `api/v{version:apiVersion}/items` already reach the document as `/api/v1/items`, and the `version` route parameter is removed. Swagger UI has no version to fill in.
- **Title**: `ApiTitleDocumentTransformer` (an `IOpenApiDocumentTransformer`) sets `info.title` to `"<ApplicationName> | v<ApplicationVersion> | Build # <APP_BUILD_NUMBER>"` from `AppSettings` and the `APP_BUILD_NUMBER` environment variable, skipping unset parts. Its `GetApiTitle` also supplies the Swagger UI page title and document name.
- **Request examples**: `RequestExampleSchemaTransformer` (an `IOpenApiSchemaTransformer`) adds an example per request DTO.
- **Summaries and descriptions**: every `src/` project sets `GenerateDocumentationFile` in `Directory.Build.props`, so controller and DTO XML comments flow into operations, parameters and schemas. These comments are public API text; developer notes belong in `//` comments. See [XML Comments Guidelines](../standards/xml-comments-guidelines.md).

`OpenApiIntegrationTests` asserts the substituted paths, title, examples and security, proves comments reach operations, parameters and schemas, requires a summary on every operation, rejects developer notes in public text, and checks that Swagger UI loads anonymously.

## Security

- **CSP**: the API-wide policy (`default-src 'none'`) would blank the page, so `/swagger` gets `default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; frame-ancestors 'none'`. Swashbuckle's page has no inline scripts; Swagger UI sets inline styles. Do not loosen the API-wide policy: `ApiPipeline:SecurityHeaders:ContentSecurityPolicy` is not set in `appsettings.json`, so ApiPipeline.NET's default applies.
- **Authorization inputs**: bearer and `x-app-*` schemes are defined centrally. An operation has one security requirement (an AND-set), never multiple requirements that would mean OR.
- **No external calls**: `ValidatorUrl` is `"none"`, so the page never contacts `validator.swagger.io`.
- **Not in Production**: keep it that way unless the UI sits behind authentication.

## Adding Another API Version

1. Register a second document: `services.AddOpenApi("v2", ...)`.
2. Add it to the UI: `options.SwaggerEndpoint("/openapi/v2.json", "v2")` in `UseSwaggerUiIfEnabled`. Swagger UI then shows a version selector.
3. Nothing else: `SubstituteApiVersionInUrl` emits `/api/v2/...` in the `v2` document, because the API Explorer groups endpoints by version (`GroupNameFormat = "'v'V"`).

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `/swagger` returns 401 | `AppSettings:Environment` is `Production`, or Swagger UI was moved after `WithAuthorization()` | Use a non-Production environment; keep the step before authentication |
| Blank page, CSP errors in the browser console | The `/swagger` CSP was removed or the path prefix changed | Keep `UseSwaggerUiIfEnabled` setting the CSP for `SwaggerUiPath` |
| "Failed to load API definition" | `/openapi/v1.json` not mapped (Production) or returns an error | Open `/openapi/v1.json` directly and check the API log |
| No summaries or descriptions | `GenerateDocumentationFile` is off for the project that declares the controller or DTO | Keep the `src/` condition in `Directory.Build.props` |
| Paths show `v{version}` | The versioned API Explorer is not substituting the version | Confirm `AddApiExplorer(...)` keeps `SubstituteApiVersionInUrl = true` in `ApiVersioningExtensions` |
